# Хос хэлтэй баримтжуулалт (en/mn pairing gate)

Дархай бол монгол хэл түрүүт нээлттэй эх төсөл: баримтын **эх нь монгол** (`docs/README.md` шиг суффиксгүй),
англи хувилбар нь `.en.md` дагаварт орчуулга (`docs/README.en.md`). Энэ хуудас нь орчуулгын хосыг
**механикаар синхрон байлгах** gate-ийн гэрээг тодорхойлно.

Гол зарчим (serge-ийн parity-gate философи): **санахад найдахгүй, CI хаана.** Нэг баримтыг засаад түүний
хосыг мартвал gate УЛААН болно. Ногоон gate нь «хоёр тал яг эдгээр байтаар нийцсэн гэж баталгаажсан» гэсэн
үг — орчуулгын чанар зөв гэсэн үг БИШ. Чанар нь ревьюгийн үүрэг хэвээр.

## Хосын гэрээ

- **Хос бүр хоёр файл.** Монгол `foo.md` ба англи `foo.en.md`, нэг хавтаст. Тусдаа locale хавтас, тусдаа
  орчуулгын репо байхгүй.
- **Opt-in manifest.** Зөвхөн [`manifest.json`](manifest.json)-д бүртгэсэн хосыг gate албадна. Дархайд одоогоор
  59 баримтаас цөөхөн нь орчуулагдсан тул бүх баримтыг албадахгүй — орчуулга хийгдэх тусам хосыг manifest-д нэмнэ.
- **Consistency бүртгэл.** Manifest дэх хос бүр хоёр талын **git blob hash**-ийг («сүүлд ижил утгатай гэж
  баталгаажсан үеийн» hash) хадгална:

  ```json
  {
    "en": "docs/README.en.md",
    "mn": "docs/README.md",
    "enHash": "1aef0e59…",
    "mnHash": "dddf04f7…"
  }
  ```

  Blob hash (commit hash биш) учир нь тэдгээр нь нэг PR дотор засагдсан файлд ч тооцоологдоно
  (`git hash-object foo.md`) ба нийцэл нь цэвэр контентын харьцуулалт болно. Нэг талыг засаад hash-ийг
  дахин бүртгэхгүй бол gate УЛААН.

- **Хэлний switcher.** Тал бүр өөрийн H1 гарчгийн дараа нөгөө тал руугаа шууд линк тавина. Монгол тал:
  `[English](foo.en.md) | Монгол`; англи тал: `English | [Монгол](foo.md)`.
- **Бүтэц нь хосоо тольдоно.** Гарчгийн гүн ба дараалал, код-блокийн байт (код орчуулагдахгүй), хүснэгтийн
  мөр/баганын тоо, линкийн тоо — хоёр талд нэг бүрчлэн таарна. (Линкийн **тоо** таарна, target биш: монгол
  `introduction.md` → `README.md` руу, англи → `README.en.md` руу заасан ч тоо ижил байвал зөв.)

## Gate: verify-translation-pairing

`bunx tsx scripts/verify-translation-pairing.ts` (CI-д ажилладаг) гэрээг механикаар албадна:

1. Manifest дэх хос бүр хоёр талтайгаа бүрэн (нэг тал дутвал = хагас газарсан орчуулга, УЛААН).
2. Тал бүрийн одоогийн blob hash нь manifest-д бүртгэсэнтэй таарна (нэгийг засаад дахин бүртгээгүй бол УЛААН).
3. Тал бүр өөрийн хосын switcher линктэй.
4. Бүтцийн сигнатур таарна: гарчгийн гүн/дараалал, код-блок verbatim, хүснэгтийн хэмжээ, линкийн тоо.

Тусгай ажиллагаа:

| Команд                                                     | Үйлдэл                                                          |
| ---------------------------------------------------------- | --------------------------------------------------------------- |
| `bunx tsx scripts/verify-translation-pairing.ts`           | Бүх manifest хосыг шалгана (CI үүнийг ажиллуулна).              |
| `bunx tsx scripts/verify-translation-pairing.ts docs/x.md` | Зөвхөн нэрлэсэн хосыг шалгана (хурдан давталт).                 |
| `bunx tsx scripts/verify-translation-pairing.ts --list`    | Хос бүрийн төлөв (ok / out-of-sync / missing). Хэзээ ч унахгүй. |

**Практик дүрэм:** PR нэг талыг засвал, ижил PR-д нөгөө талыг шинэчилж, `refresh`-ээр дахин бүртгэнэ. Хосыг
синхронгүй үлдээсэн PR CI-д УЛААН болно.

## Дахин бүртгэх: refresh-translation-pairing

Хосыг ижил утгатай болгосны дараа hash-ийг **зориудаар** дахин бүртгэнэ (автоматаар ХЭЗЭЭ Ч биш):

```bash
bunx tsx scripts/refresh-translation-pairing.ts docs/introduction.md   # нэг хос
bunx tsx scripts/refresh-translation-pairing.ts --all                  # бүх хос
```

Гарах `manifest.json`-ы diff нь «хоёр тал ижил гэж баталсан» ревью хийгдэх үйлдэл юм. `--write`-гүйгээр bulk
дахин бүртгэхийг татгалзана (`--all` шаардана) — ревью хийгээгүй хосыг чимээгүй бүү бэлэн болго.

## Gate эрүүл эсэхийг батлах: эсрэг шалгалт

Ногоон gate утгатай эсэхийг батлахын тулд gate-ийг **зориудаар эвдэж** УЛААН болохыг шалгадаг эсрэг скрипт
байх ёстой (хоосон тест ч ногоон байдаг):

```bash
bunx tsx tools/verify-translation-gate.ts
```

Энэ нь бодит `verify` CLI-г түр репо дээр ажиллуулж, дараах эвдрэл бүрийг УЛААН болгодгийг батална: тал дутуу,
hash зөрөх, бүтэц зөрөх, switcher дутуу. Мөн `refresh`-ийн дараа хос дахин ногоон болохыг шалгана. CI-д
**gate ба эсрэг шалгалт хоёулаа** ажиллана — хоёр дахийг орхивол эхнийх нь утгагүй.

## Шинэ хос хэрхэн нэмэх

1. Монгол баримтад (`docs/foo.md`) H1-ийн дараа switcher нэм: `[English](foo.en.md) | Монгол`.
2. Англи орчуулга `docs/foo.en.md` бич — бүтцийг (гарчиг, код, хүснэгт, линк) хосоороо ижил байлга,
   switcher `English | [Монгол](foo.md)` тавь.
3. `manifest.json`-ы `pairs`-д `{ "en": "docs/foo.en.md", "mn": "docs/foo.md", "enHash": "", "mnHash": "" }`
   нэм (hash-ийг түр хоосон биш, 40 тэг `0` бич).
4. `bunx tsx scripts/refresh-translation-pairing.ts docs/foo.md` ажиллуулж бодит hash бүртгэ.
5. `bunx tsx scripts/verify-translation-pairing.ts docs/foo.md` → ногоон болохыг батал.

## Санал болгосон package.json alias

Гол loop энэ хосыг нэгтгэхэд дараах script-уудыг нэмбэл ажиллагаа хялбар болно (одоогоор шууд `bunx tsx`
командаар ажиллана):

```json
{
  "docs:i18n:check": "tsx scripts/verify-translation-pairing.ts",
  "docs:i18n:list": "tsx scripts/verify-translation-pairing.ts --list",
  "docs:i18n:refresh": "tsx scripts/refresh-translation-pairing.ts",
  "docs:i18n:gate-selfcheck": "tsx tools/verify-translation-gate.ts"
}
```

## Gate-ийн хязгаар

Ногоон gate нь хос яг эдгээр байтаар нийцсэн гэж баталгаажсан гэсэн үг — баталгаа нь зөв байсан гэсэн үг БИШ.
Gate нь hash ба Markdown бүтцийг шалгана; хоёр тал үнэхээр нэг зүйл хэлж байгаа эсэх, үг сонголт үнэн зөв,
нэр томьёо тохирсон, байгалийн эсэхийг шалгаж ЧАДАХГҮЙ — энэ бол ревьюгийн үүрэг. Тал муутай хос дахин
бүртгэгдвэл gate-ийг өнгөрнө; ревьюг өнгөрөх ёсгүй.
