# Ledger: superpowers (phase 1)

> Charter contract: one row per source item, no silent omissions
> ([../CHARTER.md](../CHARTER.md) §Ledger contract). Evidence base:
> [../superpowers-dedup-verdicts.json](../superpowers-dedup-verdicts.json) (per-skill verdict entries).
>
> Decisions: **rewritten** = merged/engine-neutralized per the verdict merge_plan and vendored into
> the builtin sanctum; **converted** = vendored with adaptation, no counterpart merge;
> **dropped** = not vendored (reason given). Counterpart removals from their home pools are NOT
> executed in phase 1 — they are deferred to the phase that owns the pool (phase 2 = ECC/library,
> phase 4 = IJFW).
>
> Default-active wiring (this phase): the 12 top-level process skills are enabled by default for the
> `cowork` and `planning-with-files` builtin assistants via `PROCESS_SKILL_NAMES` in
> `src/common/config/presets/assistantPresets.ts` (flows through `getBuiltinAssistants()` →
> `enabledSkills`, `src/process/utils/initStorage.ts:616-656`); existing installs re-receive defaults
> through the `migration.builtinDefaultSkillsAdded_v3` key bump (empty/unset skill lists only — user
> customizations are preserved). `_builtin/*` (using-skills + skill-creator grafts) is auto-injected
> for every agent by `setupAssistantWorkspace` (`src/process/utils/initAgent.ts:126-152`) — no extra
> wiring, not listed in any preset.
