# 07 process-agent-managers

## Purpose

`src/process/task/` is the main-process layer that turns a conversation row into a *running agent*: it spawns/attaches the backend runtime (ACP CLI, forked Gemini worker, wayland-core Rust engine, OpenClaw/remote gateway, nanobot CLI), pipes every stream event through one canonical pipeline (transform → persist → IPC emit → team/channel buses), manages permissions/yolo auto-approval, session modes, model switching and Flux routing, injects skills/rules into prompts, detects in-message cron commands, and records per-turn cost. It is the single choke point every assimilation feature (ECC hooks, GateGuard, skill retrieval, workflow protocol) already flows through.

## Entry points & lifecycle — how and when this code runs

- **Singleton wiring**: `src/process/task/workerTaskManagerSingleton.ts:22-84` builds one `AgentFactory`, registers six creators keyed by `conversation.type` — `gemini` (:25), `acp` (:33), `openclaw-gateway` (:45), `nanobot` (:54), `remote` (:64), `wcore` (:74) — and exports `workerTaskManager = new WorkerTaskManager(agentFactory, new SqliteConversationRepository())` (:83-84). The `AgentType` union lives in `src/process/task/agentTypes.ts:10`.
- **Callers**: IPC bridges resolve managers via `workerTaskManager.getTask()/getOrBuildTask()` — e.g. `src/process/bridge/acpConversationBridge.ts:183-259`; also `conversationBridge.ts`, `geminiConversationBridge.ts`, `taskBridge.ts`, `workflowBridge.ts`, `src/process/team/TeamSessionService.ts`, `src/process/channels/agent/ChannelMessageService.ts`, `src/process/services/cron/cronServiceSingleton.ts`, and `src/process/services/workflow/dispatchAutonomousStep.ts`. Cron passes `BuildConversationOptions.yoloMode`; `skipCache` forces a fresh isolated instance (`agentTypes.ts:13-18`).
- **Creation → bootstrap**: each manager constructor kicks off an async bootstrap (`AcpAgentManager.initAgent()` lazily on first `sendMessage`, `AcpAgentManager.ts:1206-1285`; `GeminiAgentManager.createBootstrap()` eagerly, `GeminiAgentManager.ts:203`; `WCoreManager` eagerly in constructor, `WCoreManager.ts:160`; OpenClaw/NanoBot/Remote eagerly, e.g. `OpenClawAgentManager.ts:58`). All eager bootstraps attach a `.catch()` so a failed start rejects only when `sendMessage` awaits it.
- **Process model**: `BaseAgentManager extends ForkTask` and forks `path.resolve(__dirname, type + '.js')` (`BaseAgentManager.ts:41-49`) — but **only Gemini actually forks** (default `enableFork=true`); ACP, WCore, OpenClaw, NanoBot and Remote pass `enableFork=false` and drive their runtime in-process (e.g. `AcpAgentManager.ts:156`, `WCoreManager.ts:150`).
- **Idle reaping**: `WorkerTaskManager` scans every 60 s and kills `acp`/`wcore` tasks that are `finished`, not cron-busy, and idle past the timeout (default 5 min; user-configurable minutes under config key `acp.agentIdleTimeout`) — `WorkerTaskManager.ts:16-19,60-74`. Kill reasons: `'idle_timeout' | 'team_deleted'` (`IAgentManager.ts:12`).
- **Shutdown**: one shared `process.on('exit')` handler kills all live agents (`WorkerTaskManager.ts:35-47`); graceful path is `clear()` which `Promise.allSettled`-awaits every `kill()` so before-quit waits for children to die (`WorkerTaskManager.ts:121-144`, contract documented at `IAgentManager.ts:29-34`).

## Contracts & data flow

**IPC keys** (defined in `src/common/adapter/ipcBridge.ts`):
- `conversation.responseStream` = channel `'chat.response.stream'` (:110) — the unified stream. `acpConversation.responseStream` (:637-639), `geminiConversation.responseStream` (:145-148) and `openclawConversation`'s unified alias (:757) all point at it; OpenClaw additionally emits its own `'openclaw.response.stream'` (:763).
- `conversation.turnCompleted` = `'conversation.turn.completed'` (:111), emitted only by `ConversationTurnCompletionService.ts:97`.
- Confirmations: `'confirmation.add' / .update / .confirm / .list / .remove'` (:128-135), emitted through `IpcAgentEventEmitter.ts:14-27`.
- Notable `IResponseMessage.type` values produced here: `content`, `thinking`, `thought`, `start`, `finish`, `finished`, `error`, `system`, `user_content`, `request_trace` (spawn/routing badge, `AcpAgentManager.ts:941-957`, `WCoreManager.ts:793-805`, `GeminiAgentManager.ts:864-882`), `slash_commands_updated` (`AcpAgentManager.ts:890-895`), `acp_permission`, `acp_model_info`, `acp_context_usage`, `cron_propose` (`MessageMiddleware.ts:267-272`), `sub_agent_event` and `config_changed` (`WCoreManager.ts:717-750`).
- **Main-process buses** (not IPC): `teamEventBus.emit('responseStream', …)` — terminal events only, plus `acp_context_usage` for token accounting (`AcpAgentManager.ts:1056-1065`); `channelEventBus.emitAgentMessage(conversationId, …)` — every event, feeds Telegram/Lark channels.

**Spawned processes & runtimes**:
- ACP: `AcpAgentV2` (`@process/acp/compat`) spawns the backend CLI. `cliPath` resolution order: explicit `data.cliPath` → config `acp.config[backend].cliPath` → `ACP_BACKENDS_ALL[backend].cliCommand` (`AcpAgentManager.ts:801-845`); custom agents resolve from config key `assistants` or `ext:{extension}:{adapterId}` adapters (`AcpAgentManager.ts:746-789`).
- Gemini: forked Node worker `gemini.js` next to the bundle (`BaseAgentManager.ts:43`); killed+re-forked whenever the MCP fingerprint changes (`GeminiAgentManager.ts:571-594`).
- WCore: `WCoreAgent` child process (wayland-core engine); heartbeat every 30 s, kill after 3 missed pongs (`WCoreManager.ts:130-134,700-712`).
- OpenClaw gateway default port `18789` (`OpenClawAgentManager.ts:71,347`); Remote agents from DB via `db.getRemoteAgent` (`RemoteAgentManager.ts:52`).

**Env vars injected into spawns** (ACP path, `resolveAgentCliConfig`, `AcpAgentManager.ts:555-625`):
- Connected-provider API keys under each provider's well-known var from `PROVIDER_ENV_VARS`, read from `ProviderRepository` creds (`AcpAgentManager.ts:647-670`); invalid keys flip the provider to `error/unauthorized` on unambiguous auth failure (`AcpAgentManager.ts:686-713`; WCore analog `WCoreManager.ts:655-678`).
- `ECC_GATEGUARD='off'` for claude spawns only when the Settings toggle is off (`AcpAgentManager.ts:574-581`, backed by `src/process/services/eccSystemService.ts:98`).
- Flux routing (`fluxRouting.ts:120-184`): claude → `ANTHROPIC_BASE_URL/ANTHROPIC_AUTH_TOKEN/ANTHROPIC_API_KEY/ANTHROPIC_MODEL=flux-auto` (:151-170); codex → `FLUX_API_KEY` (:138-148) plus `CODEX_HOME=<userData>/flux-codex-home` (`AcpAgentManager.ts:595-603`, `codexConfig.ts:98-126`); qwen/goose → `OPENAI_BASE_URL/OPENAI_API_KEY/OPENAI_MODEL` (+`GOOSE_PROVIDER/GOOSE_MODEL`, :49-52,173-183); claude additionally gets `CLAUDE_CONFIG_DIR=<userData>/flux-claude-home` (`AcpAgentManager.ts:612-618`, `claudeConfig.ts:36-71`). Native key vars are stripped for mutual exclusivity (strip lists at `fluxRouting.ts:11-13,85-93`).
- Team/guide MCP stdio env: `AION_MCP_BACKEND`, `AION_MCP_CONVERSATION_ID` (`GeminiAgentManager.ts:435-436`, `WCoreManager.ts:287-289`), `TEAM_AGENT_SLOT_ID` handshake (`WCoreManager.ts:256-262`).

**Config/storage keys** (`ProcessConfig`): `acp.config` (per-backend cliPath/yoloMode/preferredModelId), `codex.config` (sandboxMode), `gemini.config` (proxy/yoloMode/accountProjects), `mcp.config` (MCP server list), `assistants` (custom agents), `acp.cachedModels` (Guid pre-selection, `AcpAgentManager.ts:2095-2114`), `acp.agentIdleTimeout`, `system.routeThroughFlux`, `wcore.rawEngineMode` (`WCoreManager.ts:205`).

**DB (SQLite, conversation `extra` JSON)**: session resume markers `acpSessionId`/`acpSessionConversationId`/`acpSessionUpdatedAt`/`acpWrapperVersion` (`AcpAgentManager.ts:2119-2140`), `currentModelId` (:1947-1964), `sessionMode` (:1997-2014), `cachedConfigOptions` (:2021-2034), `lastTokenUsage`/`lastContextLimit` (:1974-1992), `sessionKey` (OpenClaw :211-228 / Remote :172-189), skill state `sessionSkills`/`injectedSessionSkills`/`loadedSkills` (`agentUtils.ts:244-303`), `cronJobId` (read by `ConversationTurnCompletionService.ts:72`). Cost ledger via `getCostRecorder().recordTurnFinish` — cost_source `'engine'` (ACP cumulative gauge, `AcpAgentManager.ts:408-425`), `'computed'` (WCore `WCoreManager.ts:600-615`, Gemini `GeminiAgentManager.ts:955-969`), `'unknown'` (gateways, `OpenClawAgentManager.ts:193-205`).

**File formats**: `config.toml` `sandbox_mode` line surgery (`codexConfig.ts:46-80`); scoped flux `config.toml` with `[model_providers.flux]` (`codexConfig.ts:105-121`); scoped `settings.json` with `availableModels` (`claudeConfig.ts:61-69`); SKILL.md YAML frontmatter (`AcpSkillManager.ts:72-120`).

**In-message text protocols** (agent output is a de facto API):
- `[CRON_CREATE]…[/CRON_CREATE]`, `[CRON_PROPOSE]…`, `[CRON_UPDATE: id]…`, `[CRON_LIST]` (`CronCommandDetector.ts:50-135`); executed post-turn by `processCronInMessage` (`MessageMiddleware.ts:172-332`).
- `[LOAD_SKILL: name]` (Gemini on-demand skill loading, `GeminiAgentManager.ts:1031-1048`).
- `<think>/<thinking>` blocks incl. orphaned `</think>` (`ThinkTagDetector.ts:26-109`).
- First-message wrapper `"[Assistant Rules - You MUST follow these instructions]\n…\n\n[User Request]\n…"` (`agentUtils.ts:422,520`); system feedback prefix `"[System Response]"` (`AcpAgentManager.ts:383`, `WCoreManager.ts:966`, `GeminiAgentManager.ts:1069`); per-turn advert `"[Relevant skills for this request]"` + `"[Auto-loaded skill: name]"` (`agentUtils.ts:194,230`); `DARHAI_FILES_MARKER` splits attachments off the ranked query (`AcpAgentManager.ts:1355-1357,1412-1414`).

## Conventions & invariants

1. **Canonical stream pipeline** — every manager processes each event as: gate/filter → `transformMessage` → persist (`addOrUpdateMessage`/`addMessage`) → `ipcBridge.*.responseStream.emit` → `teamEventBus` (terminal only) → `channelEventBus` (everything). See `AcpAgentManager.handleStreamEvent` (:903-1079), `WCoreManager.init` (:714-913), `GeminiAgentManager.init` (:800-945). New managers must reproduce this order (persist before emit).
2. **Stream-text DB write buffering** — streaming text chunks are coalesced for 120 ms (`streamDbFlushIntervalMs`) before hitting SQLite, flushed on any non-text event, finish, kill, or error (`AcpAgentManager.ts:140,167-219`; `WCoreManager.ts:141,462-503`). Thinking messages use the same interval.
3. **Busy guard** — `cronBusyGuard.setProcessing(id, true)` before sending, `false` on finish/error/stop; the idle reaper and cron scheduler both consult it (`WorkerTaskManager.ts:67`).
4. **`kill()` must resolve after the child actually exits** (AUDIT-05 F20 / ForkTask M18): ACP uses agent.kill → 500 ms grace → `super.kill()`, hard-capped at 1500 ms with an idempotent guard (`AcpAgentManager.ts:2051-2089`); simpler managers `return Promise.resolve(super.kill())` (`WCoreManager.ts:1039-1050`). `WorkerTaskManager.clear()` relies on it.
5. **Error→finish pairing for channels** — a bare `error` leaves ChannelMessageService's per-conversation queue hung; always follow with a synthetic `finish` (`OpenClawAgentManager.ts:288-315`, `NanoBotAgentManager.ts:149-175`, `RemoteAgentManager.ts:252-278`).
6. **Terminal signals are never silently lost** — ACP has three fallbacks: turn-failure synthesized finish, resolved-without-activity finish, and a 15 s idle finish suppressed while a prompt is in flight (`AcpAgentManager.ts:284-497`); crashed turns also emit `turnCompleted` with `state:'error'` so autonomous workflow steps unblock (`AcpAgentManager.ts:1499-1512`).
7. **Yolo/auto-approval** — `BaseAgentManager.addConfirmation` auto-picks the first option after 50 ms in yolo (`BaseAgentManager.ts:63-73`); team-internal MCP tools (`wayland-team*`) are always auto-approved (`AcpAgentManager.ts:1102-1110`, `GeminiAgentManager.ts:728-737`); "always allow" memory lives in per-manager `ApprovalStore`s (`WCoreManager.ts:72-87`).
8. **Bootstrap gating on resume** — ACP suppresses UI stream events while `bootstrapping` (only `agent_status` passes) so `session/load` replay never re-inserts SQLite rows (`AcpAgentManager.ts:903-917,1299-1307`); a rejected bootstrap clears the cached promise so the next send re-inits instead of re-throwing forever (:1271-1283).
9. **Model/routing lockstep** — an in-place `set_model` cannot change spawn env, so a model switch that crosses the native↔flux boundary must respawn (`AcpAgentManager.setModel` :1717-1759, `respawnForRoutingChange` :1771-1808); the same `computeFluxRouting` feeds both spawn and switch (:725-735).
10. **Skill/prompt injection is centralized in `agentUtils.ts`** — do not copy-paste prompt text into managers (`searchSkillsAdvertText` note, `agentUtils.ts:24-31`); system prompts stay byte-identical turn-to-turn for prompt-cache stability; workflow protocol always appended last (“primacy at the end”, :389-394,504-509).
11. **Legacy yolo config sync** — leaving yolo mode clears the old `acp.config`/`gemini.config` `yoloMode` flag so it can't re-activate (`AcpAgentManager.ts:1929-1942`, `GeminiAgentManager.ts:1146-1158`).
12. **User dirs are never mutated** — flux routing materializes scoped homes under `app.getPath('userData')`; the real `~/.claude` and `~/.codex` stay untouched (`claudeConfig.ts:27-33`, `codexConfig.ts:83-97`); ECC hooks are written only into Darhai-owned workspaces, never `customWorkspace` (`AcpAgentManager.ts:1211-1218`).

## Assimilation anchors

1. **New agent backend / runtime** (e.g. an assimilated ECC executor or local-model runner): create `src/process/task/<X>AgentManager.ts` extending `BaseAgentManager` with `enableFork=false`, modelled on `OpenClawAgentManager.ts` (the smallest complete example: bootstrap promise, stream/signal handlers, error→finish pairing, session-key persistence, cost hook). Then (a) add the type to the `AgentType` union in `agentTypes.ts:10`, (b) register a creator in `workerTaskManagerSingleton.ts` mirroring the `openclaw-gateway` block (:45-52), (c) reuse `IpcAgentEventEmitter` unchanged. For ACP-protocol CLIs, imitate `AcpAgentManager` instead.
2. **Injecting env/config into spawned claude/codex agents** (ECC/IJFW toggles, hook env, MCP wiring): extend `AcpAgentManager.resolveAgentCliConfig` (`AcpAgentManager.ts:555-625`) — the `ECC_GATEGUARD` block (:574-581) is the exact template for a Settings-driven env toggle, and `ensureWorkspaceEccHooks` in `initAgent` (:1211-1218) is the template for materializing per-workspace hook/settings files. For giving a spawn its own scoped CLI home, imitate `claudeConfig.materializeFluxClaudeConfigDir` / `codexConfig.materializeFluxCodexHome`.
3. **New in-message command protocol** (Superpowers-style checkpoints, `[MEMORY_STORE]`, etc.): mirror the cron trio — detector like `CronCommandDetector.ts`, executor like `MessageMiddleware.handleCronCommands` (:193-332), and per-manager finish wiring at `AcpAgentManager.handleFinishSignal` (:360-387), `WCoreManager.handleTurnEnd` (:938-975), `GeminiAgentManager.checkCronCommandsOnFinish` (:1004-1081). The `[System Response]` feedback loop (collected responses re-sent to the agent) comes free if you follow the same shape.
4. **New system-prompt overlay** (constitution amendments, ECC rules, IJFW memory prelude at session start): add to `agentUtils.ts` — first-message paths are `prepareFirstMessageWithSkillsIndex` (:436-523, ACP/custom-workspace) and `buildSystemInstructionsWithSkillsIndex` (:535-578, Gemini/WCore); the `composePrompt` Constitution call (:401,515,576) and the append-last `tryComposeWorkflowProtocol` (:347-359) are the two placement patterns. All four backends pick the change up automatically.
5. **Per-turn context injection** (memory recall, retrieval augmentation): extend `buildTurnSkillContext` (`agentUtils.ts:135-236`) or add a sibling helper, then wire it at the two call sites: `AcpAgentManager.sendMessage` (:1405-1432) and `GeminiAgentManager.sendMessage` (:525-544). Follow its gates (min-terms, clear-winner margin, char cap :62-84) so injections stay cheap and non-spammy.
6. **New turn-lifecycle consumer** (metrics, autonomous orchestration): listen to `ipcBridge.conversation.turnCompleted` and feed it from managers via `ConversationTurnCompletionService.notifyPotentialCompletion` — the WCore call (`WCoreManager.ts:505-513`) is the minimal template; note the 1 s dedupe window (`ConversationTurnCompletionService.ts:23,34-42`).
