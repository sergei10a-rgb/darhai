# 15 renderer-services-common-config

## Purpose (3-5 lines)

Cross-cutting "shared substrate" of the app: the renderer-side singleton services (`src/renderer/services/*` — i18n bootstrap, file upload, paste capture, speech-to-text routing, PWA registration) and the process-agnostic configuration layer (`src/common/config/*` — typed key/value storage schemas, i18n language registry, app constants, Flux Router constants, migrations). `src/common/types/*` holds the shared type vocabulary (ACP backends, skills, memory, hwfit, IJFW...) that both main and renderer import. This area defines the **typed contracts** most other areas build on; almost every assimilation change (new setting, new UI text, new backend) touches it.

## Entry points & lifecycle — how and when this code runs

- **i18n boots at renderer module load.** `src/renderer/main.tsx:66` does a side-effect `import './services/i18n'`. That module (`src/renderer/services/i18n/index.ts`) synchronously initializes i18next with the en-US fallback bundle (lines 86-101), then asynchronously calls `initLanguage()` (line 143) which reads `ConfigStorage.get('language')` and falls back to `i18nConfig.defaultLanguage` = `mn-MN` (lines 106-110) — Darhai is Mongolian-first by deliberate design; `navigator.language` is intentionally ignored.
- **Main process has a twin i18n instance**: `src/process/services/i18n/index.ts` imports the *renderer* locale barrels statically (lines 20-27, Vite bundles them) and exposes `i18nReady` / `setInitialLanguage` / `changeLanguage` for tray/menu strings. Note it only registers 8 of the 13 locales (en, zh-CN, ja, zh-TW, ko, tr, ru, mn — no es/pt/de/fr/uk; those fall back to en-US in main-process strings).
- **PWA registration**: `registerPwa()` called once at `src/renderer/main.tsx:146`; it no-ops in Electron desktop and on insecure non-localhost origins (`src/renderer/services/registerPwa.ts:12-28`), registering `./sw.js` only in WebUI mode.
- **PasteService**: global singleton; `PasteService.init()` attaches one `document`-level `paste` listener, invoked lazily from the `usePasteService` hook (`src/renderer/hooks/file/usePasteService.ts:71`), not at boot.
- **FileService / SpeechToTextService / voice/localWhisper**: pure on-demand modules — called from sendbox/upload hooks and the voice input UI; localWhisper lazily spawns its Web Worker on first transcription (`src/renderer/services/voice/localWhisper.ts:31-76`).
- **common/config and common/types run in *both* processes.** They must stay free of DOM and Node APIs (AGENTS.md three-process rule). `storage.ts` builds its storage namespaces at module load in whichever process imports it.

## Contracts & data flow

- **Bridge storage wire keys**: every namespace built by `buildStorage` in `src/common/adapter/bridgeAllowlist.ts:106-115` registers `<namespace>.storage.{get,set,clear,remove}` in the IPC allowlist. Concretely: `agent.config.storage.get` etc. for `ConfigStorage`, likewise `agent.chat.*`, `agent.chat.message.*`, `agent.env.*` (`src/common/config/storage.ts:19-28`). Using the raw `@office-ai/platform` `storage.buildStorage` bypasses the allowlist and produces runtime "Bridge event not allowed" rejections (comment, storage.ts:10-14) — always import from `@/common/adapter/bridgeAllowlist`.
- **Config keys** (all typed in `IConfigStorageRefer`, `src/common/config/storage.ts:90-379`): notable ones for this area — `language` (159), `theme`/`colorScheme` (160-161), `tools.speechToText`/`tools.textToSpeech` (227-228), `ecc.autoInstall`/`ecc.gateGuardEnabled`/`ecc.seedInProgress` (185-198, GateGuard off injects `ECC_GATEGUARD=off` into claude spawns), `ijfw.skipSetup` (180), `skills.preferences` (341-348), `migration.*` one-shot flags (242-270), template-typed `assistant.<platform>.{defaultModel,agent}` for 25 channel platforms (40-88).
- **Chat history**: `IChatConversationRefer['chat.history']` (storage.ts:678-680) holds `TChatConversation[]` — 7 variants (`gemini`, `acp`, `codex`, `openclaw-gateway`, `nanobot`, `remote`, `wcore`); `extra.projectId`/`extra.cronJobId` are read DB-side via `json_extract(extra,'$.projectId')` (storage.ts:442).
- **i18n IPC**: renderer→main `ipcBridge.systemSettings.changeLanguage` = provider key `system-settings:change-language` (`src/common/adapter/ipcBridge.ts:927`); main→all-renderers broadcast `languageChanged` = emitter key `system-settings:language-changed` (ipcBridge.ts:929). Flow: `changeLanguage()` (renderer i18n index.ts:161-173) → persist `ConfigStorage.set('language')` → invoke main → main rebroadcasts → other renderers `ensureAndSwitch` (index.ts:148-156). `localStorage['i18nextLng']` is only a first-paint hint — deliberately no i18next browser-languagedetector because WebUI localStorage is a different origin than the Electron renderer (Issue #1176; index.ts:80-85).
- **i18n file formats**: locale module = plain nested JSON under `src/renderer/services/i18n/locales/<lang>/<module>.json`; barrel `<lang>/index.ts` maps module-name → JSON. Key typing derives ONLY from `referenceLanguage` (en-US) × `i18n-config.json#modules` (`scripts/generate-i18n-types.js:19-57`); `scripts/check-i18n.js` validates completeness of every language against the reference and that `i18n-keys.d.ts` is fresh. Both run in CI; also required locally per AGENTS.md ("i18n validation").
- **Renderer HTTP endpoints** (WebUI mode): `POST /api/upload` multipart with `_csrf` in body (`FileService.ts:33-41`), `POST /api/stt` multipart (`SpeechToTextService.ts:95`). Both `withCredentials`, both map HTTP 413 → typed `*_TOO_LARGE` errors.
- **Spawned runtimes**: `voice/localWhisper.ts` spawns one module Web Worker (`src/renderer/workers/whisperWorker.ts`) with message protocol `{type:'init',modelBase}` / `{type:'transcribe',requestId,audio}` → `{ready|result|error}` (localWhisper.ts:21-24, 63, 126); model assets served from main via `ipcBridge.voiceAsset.localModelBase` (line 50).
- **Env vars read here**: `NODE_ENV` + `DARHAI_MULTI_INSTANCE` select the WebUI port (constants.ts:55-59); `DARHAI_MULTI_INSTANCE` also switches dev dir suffix (appEnv.ts:21).
- **localStorage keys**: the six `wayland_*` keys in storageKeys.ts:15-33 plus i18next's `i18nextLng` (i18n index.ts:94, 114).

## Conventions & invariants

- **All user-facing text goes through i18n keys** — never hardcoded strings (AGENTS.md; enforced by `.claude/skills/i18n/SKILL.md`). Keys are `module.key` / `module.nested.key`; the module must exist in `i18n-config.json#modules`, the key must exist in en-US (reference), and every one of the 13 languages must have the module file (check-i18n.js fails otherwise). After adding keys: `bun run i18n:types && node scripts/check-i18n.js`.
- **Never edit `i18n-keys.d.ts` by hand** — regenerate. Never edit locale barrels inconsistently: adding a module means i18n-config.json + all 13 `<lang>/index.ts` barrels + all 13 JSON files.
- **`ConfigStorage` is the single source of truth for language** (and other prefs); localStorage is a cache/hint only. New persisted settings = add a typed key to `IConfigStorageRefer` first (compile-time contract), then read/write via `ConfigStorage` — never invent ad-hoc localStorage keys (those belong in `storageKeys.ts` and are UI-ephemera only, `wayland_*` prefix).
- **One-shot migrations** follow the `migration.<name>` boolean-flag pattern (storage.ts:242-270; executed like `skillsMigration.ts:29-57` — guard-read, do work, set flag). New data-shape changes must add a new flag, never reuse one.
- **Platform branching pattern**: renderer services must handle both Electron desktop (IPC via `ipcBridge`) and WebUI (HTTP + CSRF), keyed off `isElectronDesktop()` (`src/renderer/utils/platform`) — see FileService.ts:283-299, PasteService.ts:24-41, SpeechToTextService.ts:76-120. Any new renderer service with I/O must implement both arms.
- **common/ imports nothing process-specific**: no DOM, no Node, no `@process/*` (except type-only, e.g. FileService's `csrfClient` import is a renderer file importing a shared client util). Renderer-visible mirrors of process types are hand-duplicated with a "keep in sync" note (hwfit.ts:9-14 pattern).
- **Typed error strings as contract**: cross-boundary errors are SCREAMING_SNAKE codes (`FILE_TOO_LARGE`, `STT_FILE_TOO_LARGE`, `STT_NETWORK_ERROR`, IJFW `errorReason` enum) that the UI maps to i18n keys — do not throw free-text errors across layers.
- **Legacy naming caution**: `wayland`/`AION` strings inside constants (`_wayland_` timestamp separator, `[[AION_FILES]]`, `wayland_*` localStorage keys, `wayland-skills`, `'wayland'` ConversationSource) are **wire/persisted formats**, not brand leftovers — renaming them breaks existing user data. Treat as frozen identifiers.

## Assimilation anchors — concrete plug-in points

1. **New persisted setting (e.g. ECC/Odysseus feature toggle)** → add a typed optional key to `IConfigStorageRefer` in `src/common/config/storage.ts`, imitating `'ecc.gateGuardEnabled'` (storage.ts:186-191) — a documented, defaulted, optional key read via `ConfigStorage.get`. If it gates a spawn-time env var, follow the same GateGuard pattern (config key → env injection in the process-side spawner).
2. **New i18n module for a new feature page** → (a) add module name to `src/common/config/i18n-config.json#modules`; (b) create `<module>.json` in all 13 `src/renderer/services/i18n/locales/<lang>/` dirs; (c) add import+export to each `<lang>/index.ts` barrel (imitate `locales/en-US/index.ts`); (d) `bun run i18n:types` + `node scripts/check-i18n.js`. Closest analog: the `models` module (last added, present in every barrel). Note mn-MN's untracked `conversations`/`archive`/`wiki` modules (mn-MN/index.ts:38-40) as the anti-pattern to fix: modules outside i18n-config.json get no typing or validation.
3. **New renderer singleton service (e.g. an Odysseus voice/automation client)** → new file in `src/renderer/services/`, imitating `PasteService.ts` (class + exported singleton, explicit `init()`/`destroy()`, handler registry) for event-driven services, or `SpeechToTextService.ts` for request/response services with the Electron-IPC-vs-WebUI-HTTP dual arm. Heavy compute goes in a Web Worker owned by the service, imitating `voice/localWhisper.ts` (lazy `ensureWorker`, requestId map, transferable payloads).
4. **New one-shot data migration (e.g. importing ECC skill preferences)** → dedicated `src/common/config/<name>Migration.ts` imitating `skillsMigration.ts` (store-interface parameter for testability, `migration.<name>_v1` guard flag declared in `IConfigStorageRefer`).
5. **New shared type surface for a merged capability (e.g. Superpowers workflow states)** → new file in `src/common/types/`, imitating `ijfw.ts`: const-array + derived union for enum codes (so both runtime validation and typing exist), an `InvokeResult`-style ok/error envelope, and error codes designed to map 1:1 to i18n keys. If the process side has richer internal types, mirror only the renderer-needed subset with a sync note, imitating `hwfit.ts:9-14`.
6. **New CLI-agent backend (assimilating another agent runtime)** → extend `AcpBackendAll` and, if wrapper-pinned, the version constants + `getCurrentWrapperVersion` switch in `src/common/types/acpTypes.ts:7-38`; conversation persistence comes free via the `acp` variant of `TChatConversation` (storage.ts:446-503).
