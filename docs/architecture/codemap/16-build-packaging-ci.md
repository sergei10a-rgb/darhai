# 16 build-packaging-ci

## Purpose (3-5 lines)

Everything that turns the TypeScript tree into a shippable installer: the electron-vite bundling config, the `scripts/` build pipeline (vendored-payload staging, engine-binary download + SHA-256 verification, native-module rebuild, Electron fuse hardening), the electron-builder packaging map (`files` / `extraResources` / `asarUnpack`), dev-time codegen/validation (i18n types + check), and the GitHub Actions workflows that gate PRs and cut releases. This area is also where every "ship X inside the installer" decision is made — all bundled capabilities (ECC, IJFW, wayland-core, bun, voice model, hub extensions) enter the app through the `prepare*.js` → `extraResources` → `process.resourcesPath` chain.

## Entry points & lifecycle — how and when this code runs

- **`bun install`** → `postinstall` script (`package.json` "postinstall", scripts/postinstall.js:190) runs on every install: widens override-pinned dep ranges, installs whatsapp-bridge deps, and (local only, not CI) runs `electron-builder install-app-deps` (scripts/postinstall.js:162-182).
- **`bun start`** (`electron-vite dev`) → electron.vite.config.ts in `development` mode; the dev-only `dev-build-mcp-servers` plugin re-bundles builtin MCP servers on `closeBundle` (electron.vite.config.ts:66-77).
- **`bun run dist[:win|:mac|:linux]`** → `predist` runs `scripts/bundle-modelsdev.ts`, then **scripts/build-with-builder.js** — the single build orchestrator. Order (scripts/build-with-builder.js:399-473): (1) `bunx electron-vite build` (skippable via source-hash incremental cache `out/.build-hash`, line 30/126), (2) `scripts/build-mcp-servers.js` re-bundle, (3) `prepareBundledBun()`, (4) `prepareHubResources.js`, (5) `prepareIjfw.js`, (6) `prepareEcc.js`, (7) `prepareWaylandCore()`, (8) `prepareVoiceModel.js`, (9) `bunx electron-builder … --publish=never` (line 550).
- **During electron-builder packaging**: `afterPack: scripts/afterPack.js` and `afterSign: scripts/afterSign.js` hooks fire per target (electron-builder.yml:278-279).
- **Dev-time codegen**: `bun run i18n:types` → scripts/generate-i18n-types.js; `node scripts/check-i18n.js` runs in pre-commit/prek and in the CI "I18n Check" job (.github/workflows/pr-checks.yml:331-381).
- **CI**: PRs run pr-checks.yml (no packaging, `WCORE_SKIP=1`); pushes to `dev` and version tags run build-and-release.yml → _build-reusable.yml (6-platform packaged matrix, `WCORE_SKIP=0`) → draft GitHub Release.

| --- | --- | --- | --- |

| `resources/bundled-wayland-core/{plat}-{arch}/wayland-core[.exe]` + `manifest.json` | `bundled-wayland-core` | prepareWaylandCore.js | engine spawn (area 08) |

**Env vars (build-time)**: `ECC_SKIP` / `ECC_REFRESH` / `ECC_LOCAL_SOURCE` / `ECC_PIN_SHA` (prepareEcc.js:30-35); `IJFW_SKIP` / `IJFW_INSTALL_VER` (prepareIjfw.js:14-17); `WCORE_SKIP` / `DARHAI_CORE_SKIP` / `WCORE_VERSION` / `WCORE_ARCH` / `WCORE_FORCE_DOWNLOAD` / `WCORE_USE_LOCAL` / `WCORE_REQUIRE_VERIFIED` (prepareWaylandCore.js:18-24, 104-118, 365-374); `DARHAI_BUN_VERSION` (prepareBundledBun.js:50); `DARHAI_HUB_TAG` / `DARHAI_HUB_SKIP` (prepareHubResources.js:10-12); `FORCE_NATIVE_REBUILD` (afterPack.js:87); `SENTRY_DSN` / `SENTRY_AUTH_TOKEN` / `SENTRY_ORG` / `SENTRY_PROJECT` (electron.vite.config.ts:44-58); `ELECTRON_BUILDER_COMPRESSION_LEVEL` (build-with-builder.js:485); `GH_TOKEN`/`GITHUB_TOKEN` for release-asset auth (prepareWaylandCore.js:203, 256-280); `DARHAI_MULTI_INSTANCE` baked into the renderer bundle via `define` (electron.vite.config.ts:278).

**Release-build detection** (prepareWaylandCore.js:104-118): `CI`, `NODE_ENV=production`, `npm_config_production`, `npm_lifecycle_event` matching `^(dist|build|make|package)`, or `WCORE_REQUIRE_VERIFIED=1` — when true, SHA-256 verification is mandatory and no `WCORE_*` env can bypass it (RT-B6-06).

**File formats**: `scripts/bundled-{bun,wcore}-shasums.json` — `{ "<tag>": { "<assetName>": "sha256hex" } }` (loadExpectedShaForAsset, prepareWaylandCore.js:126-159); `resources/bundled-wayland-core/<key>/manifest.json` — `{platform, arch, version, generatedAt, sourceType, source, sha256, files, skipped, reason?}`; `src/common/config/i18n-config.json` — `{referenceLanguage, supportedLanguages, modules}` drives both i18n scripts; `out/.build-hash` — md5 incremental-build cache.

**CI naming contracts**: job names `Code Quality`, `Unit Tests (<os>)`, `Coverage Test`, `I18n Check`, `Security Audit E2E`, `Release Script Test` are branch-protection required checks mirrored by pr-checks-docs.yml — renaming requires touching both files + repo settings (pr-checks.yml:10-15). `artifactName: ${productName}-${version}-${os}-${arch}.${ext}` must stay ASCII for electron-updater `latest.yml` lookup (electron-builder.yml:2-9).

## Conventions & invariants

- **Everything shipped is pinned + verified.** Third-party payloads either live committed in git (ECC — "vendoring, not build-time fetching", prepareEcc.js:10-13) or are fetched at a pinned version and SHA-256-checked against a committed shasums manifest before extract/copy/execute (bun, wayland-core). A release build fails closed rather than shipping unverified bytes; bypass env vars are dev-only by construction.
- **No runtime download fallback for the engine.** `WCORE_SKIP=1` builds ship engine-less permanently (prepareWaylandCore.js:369-374); only the release path (`_build-reusable.yml` `WCORE_SKIP: '0'`) bundles it. PR/test workflows always skip.
- **prepare scripts are idempotent, non-destructive, and each writes a manifest or logs a versioned summary**; each is independently runnable (`if (require.main === module)`) and also callable from build-with-builder.js.
- **Binary/spawned things live outside app.asar.** Anything `fork()`ed, `spawn()`ed, `dlopen`ed, or read as a real file goes through `extraResources` or `asarUnpack` (electron-builder.yml:123-185, 312-363); pure-JS deps stay in the asar. Builtin MCP servers additionally must be esbuild-self-contained because external `node` has no asar support (build-mcp-servers.js:4-11).
- **`productName` stays ASCII** ("Darhai"); Mongolian branding only on user-visible NSIS strings + i18n (electron-builder.yml:2-10).
- **Fuses before signing**: afterPack flips fuses, afterSign signs/notarizes — order matters on macOS (afterPack.js:38-42).
- **GitHub Actions are pinned to full commit SHAs** (every `uses:` line in all 8 workflows), and no untrusted PR text is interpolated into `run:` steps (pr-checks.yml:27-29, build-matrix.yml:1-8).
- **i18n codegen is checked, not trusted**: `i18n-keys.d.ts` is generated but committed; check-i18n.js fails CI/pre-commit if it drifts from the reference locale (check-i18n.js:70-98).
- **CI publishes drafts only**: build-with-builder.js always passes `--publish=never` (line 478); the release job is the sole publisher and creates `draft: true` releases.

## Assimilation anchors — concrete plug-in points

1. **New bundled offline payload (e.g. Superpowers/Odysseus skill packs)** — mirror `scripts/prepareEcc.js` exactly: commit the audited payload to `resources/bundled-<name>/`, write a `prepare<Name>.js` with verify-default + `--refresh` re-vendor + smoke-install assertion, wire it into `scripts/build-with-builder.js` (insert next to line 461-464 where prepareIjfw/prepareEcc run), and add one `extraResources` pair in electron-builder.yml (after the `bundled-ecc` block, line 143-144). Runtime consumer follows `src/process/services/eccSystemService.ts` (resolve via `process.resourcesPath`, seed into the user dir on first run).
2. **New per-platform binary dependency** — mirror `scripts/prepareWaylandCore.js` + `scripts/bundled-wcore-shasums.json`: pinned tag constant, `loadExpectedShaForAsset` → download → `verifyArchiveChecksum` before extract/exec, `manifest.json` output, `<NAME>_SKIP` env honored by PR workflows, verification mandatory under `isReleaseBuild()`. Register the skip env in pr-checks.yml/build-matrix.yml `env:` and force-enable in _build-reusable.yml.
3. **New pure-JS npm-staged seed (MCP server, agent runtime)** — mirror `scripts/prepareIjfw.js`: `npx <pkg>@<PINNED> … --dir <staging>`, prune, copy to `resources/bundled-<name>`, extraResources entry, first-run seeding service modeled on `src/process/services/ijfwSystemService.ts`.
4. **New builtin MCP server shipped in the installer** — add an esbuild entry in `scripts/build-mcp-servers.js` (CJS via `SHARED_OPTIONS` or ESM via `bundleWaylandMcp`, lines 20-50) and an `asarUnpack` line for the emitted `out/main/<name>.{js,mjs}` (electron-builder.yml:342-350, pattern: `builtin-mcp-*.mjs`).
5. **New i18n module** — add the module name to `src/common/config/i18n-config.json` `modules`, create `<module>.json` in every `src/renderer/services/i18n/locales/<lang>/`, run `bun run i18n:types`, and `node scripts/check-i18n.js` must pass; both scripts pick the module up automatically from the config (generate-i18n-types.js:19-21, check-i18n.js:11-18).
6. **New CI gate** — add a job to pr-checks.yml AND a same-named stub to pr-checks-docs.yml (required-check name contract, pr-checks.yml:10-15); packaged-build checks go to build-matrix.yml (flag-gated), never into the PR path.
